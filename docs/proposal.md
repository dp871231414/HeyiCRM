# 合一重卡生态经营看板 · 产品需求说明（proposal）

> 版本：v2.0 · 2026-10-17
> 状态：已评审 · 当前实现基线
> 依据：原型 `经营看板/`（经多轮业务确认）+ 已锁定决策基线 + Round 23 改造（车头/挂车需求子列表、系统配置-数据字典、导入模板精简）
> 说明：本文回答「做什么、为什么、做到什么程度」，不含技术实现细节。技术方案见 `design.md`，测试结论见 `test-report.md`。

## 1. 项目背景

合一重卡生态是围绕新能源重卡展开的「销售 — 运力 — 补能 — 租赁」一体化业务，由一家总部（全公司）统一管理，下设市场、资产、运营、补能、技术支持、财务、金融、行政、人事、数智化、法务共 11 个二级部门，另有 3 家独立核算的项目运营公司（重卡运营、补能运营、车辆租赁）。

当前经营数据分散在各部门台账与临时表格中，月度经营会前由人工汇总，存在三个直接后果：口径不统一、汇总滞后、责任无法追溯到组织与个人。本项目旨在建立一个由总部统一承载、按组织与角色分权使用的经营看板系统，把「目标下达 — 数据填报 — 达成判定 — 风险提示」固化为线上闭环。

项目已完成高保真原型，并演进为前后端分离、可正式部署的生产级应用。

## 2. 要解决的问题

| 编号 | 问题 | 现状 | 期望 |
|---|---|---|---|
| P-1 | 口径不统一 | 各部门各算各的，同一指标出现多个版本 | 指标口径、单位、方向、阈值在系统内唯一定义，全公司共用 |
| P-2 | 汇总滞后 | 月度经营会前人工拉表，1~2 天出不来 | 线上填报即生效，看板实时聚合 |
| P-3 | 责任不清晰 | 指标缺口说不清该谁负责 | 每个指标、每项任务绑定责任组织与责任人，缺口可下钻定位 |
| P-4 | 权限无隔离 | 全员共用一套账号，谁都能看全公司数据 | 按组织与角色分权，可见范围与可操作按钮双重管控 |
| P-5 | 组织无法维护 | 部门、项目公司调整要改代码 | 部门与项目公司支持在线增删改，任务与指标自动跟随 |
| P-6 | 风险靠人盯 | 逾期、异常、未达标指标靠人记 | 系统按规则自动判定红黄绿灯、临期逾期，并生成结论文案 |
| P-7 | 车辆需求缺结构化 | 车头/挂车需求只用两个汇总数字，丢失「车型/电池/数量」明细 | 车头/挂车需求以可增删的子列表录入，列表展示汇总，明细可追溯 |
| P-8 | 车型无统一来源 | 车型靠手填，易错且不可统一维护 | 车辆型号/挂车型号由系统数据字典维护，表单下拉取值 |
| P-9 | 导入模板过重 | 项目导入要求填牵引车/挂车需求，与「先建项目、再补车辆需求」的实际流程脱节 | 导入仅填项目信息，车辆需求在系统内补充 |

## 3. 目标用户

| 角色 | 典型人员 | 使用场景 | 关注点 |
|---|---|---|---|
| 系统管理员 | 陈志明（数智化/运营负责人） | 维护组织与账号、配置角色权限、管理指标口径、维护数据字典 | 全公司数据可控、账号安全 |
| 部门负责人 | 王建国（财务）、林雪（市场）等 11 人 | 查看本部门及下属部门任务与指标、录入数据 | 本部门达成情况、缺口与风险 |
| 普通成员 | 郑凯、何欣等 | 维护指派给自己的任务、录入本人指标 | 本人任务进度、是否临期逾期 |
| 项目公司负责人 | 李强（重卡运营）、周敏（补能）、高翔（租赁） | 维护本公司运营车辆/收入/回款/利润 | 本公司经营指标达成 |

使用环境：PC 浏览器（Chrome / Edge / Safari 最新两个大版本），会议室投屏（1920×1080）与办公本（1366×768）为主，窄屏（≥1024px）可用。

## 4. 核心目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-1 | 月度数据一次填报、全员同源可见 | 指标录入保存后，驾驶舱与维护页读数一致，无二次汇总 |
| G-2 | 达成判定与风险提示自动化 | 红黄绿灯、临期/逾期、分析总结全部由系统按规则生成，零人工判断 |
| G-3 | 数据按组织与角色严格隔离 | 任一角色登录后不可见越权组织的数据，且不可操作无权限按钮 |
| G-4 | 组织与账号可自助维护 | 部门、项目公司、账号、角色的增删改全部在线完成，无需改代码 |
| G-5 | 系统可正式部署 | 单端口同源托管（后端 + 前端），支持环境变量外置；数据字典等配置在线维护 |
| G-6 | 车辆需求结构化、车型可配置 | 车头/挂车需求以子列表录入并展示汇总；车型由数据字典统一维护 |

## 5. MVP 功能范围

### 5.1 登录与会话（AUTH）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| A-1 | 账号 + 密码登录 | 正确凭据进入系统；错误凭据提示「账号或密码错误」且不泄露账号是否存在 |
| A-2 | 登录态保持与登出 | 刷新页面保持登录；登出后回到登录页且本地凭据清除 |
| A-3 | 登录记录 | 记录每次登录的时间与 IP，管理员可在账号页查看最近登录时间 |
| A-4 | 停用账号限制 | 状态为「停用」的账号登录被拒绝并提示 |

### 5.2 组织管理（ORG）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| O-1 | 组织树展示 | 以「全公司 → 二级部门 → 子部门」层级展示，默认全展开可见层级缩进 |
| O-2 | 部门新增/编辑 | 可在全公司下新增二级部门，可在任意部门下创建子部门，可改名称与负责人 |
| O-3 | 部门删除约束 | 部门下有账号时禁止删除（仅可修改）并给出原因；部门有下级部门时禁止删除 |
| O-4 | 项目公司维护入口分离 | 项目公司不在组织树内维护，新增/编辑/删除统一在「指标维护」页完成 |
| O-5 | 部门调色与任务跟随 | 删除部门时，该部门下任务自动上移至其上级部门，不产生无归属数据 |

### 5.3 角色与权限（ROLE）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| R-1 | 角色列表与查询 | 列表展示角色名称、说明、数据可见范围、关联账号数，支持按名称搜索 |
| R-2 | 角色新增/编辑 | 编辑界面可勾选「菜单权限」与「按钮权限」，可设置数据可见范围四类之一 |
| R-3 | 菜单权限联动 | 取消父级菜单权限时，其下按钮权限自动取消勾选 |
| R-4 | 角色删除约束 | 内置角色（系统管理员/部门负责人/普通成员）不可删除；角色下有账号时不可删除 |

### 5.4 账号管理（ACCOUNT）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| U-1 | 账号列表与查询 | 展示姓名、账号、所属部门、角色、状态、最近登录，支持搜索与筛选 |
| U-2 | 账号新增/编辑 | 可设置姓名、账号、初始密码、所属部门、角色、状态 |
| U-3 | 所属部门取值范围 | 部门选项与组织管理一致（全公司 + 各部门层级缩进），不含项目公司 |
| U-4 | 数据可见范围 | 可选「跟随角色默认 / 本人 / 本部门 / 本部门及下属部门 / 全公司」，账号值可覆盖角色默认值 |
| U-5 | 启停用 | 可停用/启用账号；停用后不可登录 |
| U-6 | 批量导入/删除 | 按模板批量导入账号（任一行错误整批不写）；仅当账号未被任何数据引用时可删除 |

### 5.5 指标维护（METRIC）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| M-1 | 指标三组结构 | 维护页纵向排列三模块：①公司整体目标 ②指标监控 ③项目公司指标 |
| M-2 | 指标口径唯一定义 | 每个指标含编码、名称、单位、方向、所属组、权重、责任部门、口径说明 |
| M-3 | 录入即生效 | 录入年度目标/完成值/回款，保存后立即影响驾驶舱读数，无审核环节 |
| M-4 | 年度目标按年度存储 | 年度目标与项目公司目标按「年份」存一份，全年各月度周期共用 |
| M-5 | 完成率口径 | 完成率 = 累计完成 / 年度目标；收入/消化/利润为**年初至今累计**，运营车辆为**期末快照** |
| M-6 | 回款口径 | 回款率 = 累计回款 / 累计收入完成值；目标回款率默认 95%，≥目标绿、低 5 个百分点内黄、其余红 |
| M-7 | 时间进度对比 | 展示年度时间进度（按数据截至日计算）与「完成率 vs 时间进度」差值 |
| M-8 | 监控指标 | 事故/故障/租金减免等 10 项监控指标无目标值、无红黄绿灯，仅统计展示当月快照 |
| M-9 | 项目公司列表化增删 | 项目公司模块以列表呈现，每公司一行含目标/完成行内录入、完成率、达成徽标、保存/编辑/删除 |
| M-10 | 项目公司删除影响面 | 删除前提示影响面；删除后连带清理其指标数据、任务，关联账号停用 |
| M-11 | 与驾驶舱联动定位 | 驾驶舱点「去维护」可定位到对应指标行并高亮 |
| M-12 | 状态口径统一 | 单指标与汇总统计共用同一套状态判定（`progress_tone`：完成率 ÷ 时间进度），标签一致 |

### 5.6 任务管理（TASK）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| T-1 | 任务列表字段 | 列含：任务ID、主任务、任务名称、任务分类、责任人、责任部门、创建人、目标、已完成、完成进度、计划起止、创建时间、更新时间、状态、操作 |
| T-2 | 冻结列与横滑 | 表格超宽时左右滑动，任务ID/主任务/任务名称冻结在左、操作列冻结在右 |
| T-3 | 任务新增/编辑 | 新建弹窗字段与列表一致 + 描述、是否异常、目标、已完成、单位、进展描述、起止日期、责任部门、责任人 |
| T-4 | 完成进度自动计算 | 完成进度 = 已完成 / 目标，不接受手填百分比 |
| T-5 | 临期/逾期自动判定 | 剩余天数 = 计划结束日期 − 今天；≥1 天正常、0≤剩余<1 天临期、<0 天逾期；已完成任务不再判逾期 |
| T-6 | 任务健康度 | 时间判定叠加人工「是否异常」标记；异常且未完成显示「异常」 |
| T-7 | 任务筛选 | 支持按关键字、责任部门、状态筛选 |
| T-8 | 任务批量导入 | 按标准模板导入，逐行校验；任务名称相同的多行自动归组为同一公司级任务 |
| T-9 | 主任务字典 | 任务分类由后台独立「主任务」字典维护，支持下拉选择与新增；主任务 ID 不可变、名称可改 |
| T-10 | 进展时间轴 | 任务进展以时间轴记录，可追加；编辑不可直改进展，只能追加新记录 |

### 5.7 经营驾驶舱（DASH）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| D-1 | 规则生成分析总结 | 顶部展示「整体结论 + 亮点 + 风险 + 建议」，由确定性模板拼装，不引入 AI |
| D-2 | 整体结论含加权达成率 | 显示综合加权达成率、达标/接近/未达标项数、年度时间进度及跑赢/落后说明 |
| D-3 | 核心指标卡片 | 年度目标以卡片展示，收入类卡片含回款行；卡片显示目标/完成/完成率/状态与时间进度对比 |
| D-4 | 项目公司对比区 | 公司视角展示 3 家项目公司的运营车辆/运营收入/回款/利润对比，每行可「去维护」 |
| D-5 | 监控指标区 | 展示事故/故障/租金减免当月亮化数据 |
| D-6 | 部门任务完成度 | 按部门展示任务完成统计卡（任务数/已完成/逾期/异常），支持口径筛选（全部/本年新增/当月新增/未结束） |
| D-7 | 风险与异常清单 | 汇总红灯指标、环比走弱指标、不健康任务，置于页面文末，点击可定位 |
| D-8 | 市场项目概览 | 项目转化漏斗 + 车辆/挂车需求漏斗（当前阶段口径）+ 销量预测（按阶段转化概率加权） |
| D-9 | 漏斗口径稳定 | 驾驶舱漏斗读车头/挂车需求**汇总值**，项目管理子列表改动不影响驾驶舱口径 |

### 5.8 项目管理（MARKET · 含车头/挂车需求子列表）

市场项目（商机）与「项目公司」是两个概念：本模块是销售线索/商机，按阶段推进，是驾驶舱「市场项目概览」漏斗的数据来源。

| 编号 | 需求 | 可验证点 |
|---|---|---|
| K-1 | 车头需求子列表 | 编辑表单内以**表格**录入车头需求：每行含 车辆型号（下拉，取自数据字典 `vehicle_model`）、电池度数、数量；可加多行、可删除行；列头直接展示字段名（车辆型号/电池度数/数量/操作） |
| K-2 | 挂车需求子列表 | 同理，挂车型号下拉取自数据字典 `trailer_model`；列头展示 挂车型号/电池度数/数量/操作 |
| K-3 | 列表汇总展示 | 项目管理列表列名 车头需求→**车头数量**、挂车需求→**挂车数量**，展示各明细行「数量」的**汇总值** |
| K-4 | 驾驶舱不变 | 驾驶舱漏斗仍读车头/挂车需求汇总值（与 `tractor_demand`/`trailer_demand` 一致），口径不受子列表改造影响 |
| K-5 | 明细可追溯 | 项目详情展示车头/挂车需求的明细行（车型 + 电池 + 数量），列表列展示汇总 |
| K-6 | 阶段取值固定 | 项目阶段固定为 10/25/50/75/90/100（项目导入/市场尽调/初审通过/联合评审通过/签约落地/交车投运） |
| K-7 | 数据权限 | 按创建人所属部门匹配可见范围；本人创建的项目始终可见；range 外读/改/删 403 |

### 5.9 系统配置 · 数据字典（SYSTEM）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| S-1 | 系统配置菜单 | 新增一级菜单「系统配置」，下含子菜单「数据字典」；菜单可见性受 `sys.config.view` 控制 |
| S-2 | 数据字典 CRUD | 添加字典（字典名称 + 编码 + 枚举值多行）、编辑（枚举值整份替换、可增删多行）、删除 |

| S-6 | 字典可维护 | 字典名称、编码、枚举值均可在系统内修改，无需改代码 |

## 6. 用户操作流程

### 流程一 · 管理员初始化

```
登录（管理员）→ 账号管理·组织结构（确认部门）→ 角色权限（配置各角色菜单与按钮权限，含系统配置）
→ 账号管理（新增账号、设定所属部门与可见范围）→ 系统配置·数据字典（确认车型预设或新增）
→ 指标维护（设定年度目标）→ 任务管理（导入或新建任务）→ 通知各部门填报
```

### 流程二 · 部门/成员月度填报

```
登录 → 指标维护（录入本部门/本人指标完成值、回款）→ 保存（立即生效）
→ 任务管理（更新「已完成」、进展描述、是否异常）→ 驾驶舱确认读数正确
```

### 流程三 · 项目管理录入车辆需求

```
登录（有 market.edit）→ 项目管理 → 新建/编辑项目 → 填写项目信息
→ 在「车头需求」表格逐行添加（车辆型号下拉 + 电池度数 + 数量）；「挂车需求」同理
→ 保存 → 列表「车头数量/挂车数量」展示各行数量汇总；详情可见明细
```

### 流程四 · 维护数据字典（车型）

```
登录（有 sys.config.edit）→ 系统配置 → 数据字典 → 选择「车辆型号」字典
→ 编辑枚举值（增删多行，如新增「换电牵引车」）→ 保存
→ 返回项目管理，车头需求「车辆型号」下拉即出现新选项
```

### 流程五 · 月度经营会

```
登录（管理员）→ 经营驾驶舱 → 阅读分析总结 → 点风险条目定位到指标或任务 → 去维护页修正 → 返回复核
```

## 8. 异常场景

| 编号 | 场景 | 期望行为 |
|---|---|---|
| E-1 | 账号或密码错误 | 提示「账号或密码错误」，不区分账号不存在与密码错误 |
| E-2 | 账号被停用 | 登录被拒，提示「账号已停用，请联系管理员」 |
| E-3 | 登录态过期 | 请求返回未授权时，自动跳转登录页并提示「登录已过期，请重新登录」 |
| E-4 | 无权限访问页面/按钮 | 侧边栏不出现无权限菜单；直接访问受限页面显示无权限提示；无权限按钮不渲染 |
| E-5 | 越权访问数据 | 后端按可见范围强制过滤，即使前端构造请求也拿不到越权数据 |
| E-6 | 目标值为 0 | 按绝对值判定，不套用比率，不出现除零 |
| E-7 | 实际值缺失 | 达成率显示「—」，状态为「未录入」，不参与加权统计 |
| E-8 | 收入为 0 时算回款率 | 回款率显示「—」，不出现除零或 Infinity |
| E-9 | 逆向指标实际值为 0 | 视为达标（如零事故），达成率按达标处理 |
| E-10 | Excel 行数据非法 | 该行不进库，整批高亮错误行并列出错误明细 |
| E-11 | Excel 责任人/部门不存在 | 报错「不是系统内已有账号姓名 / 不是有效的组织名称或编码」 |
| E-12 | 删除有账号的部门 | 拒绝并说明「该部门下有 N 个账号，不允许删除，仅可修改」 |
| E-13 | 删除有账号的角色 | 拒绝并说明「该角色下仍有 N 个账号，请先调整这些账号的角色」 |
| E-14 | 重名组织/角色/项目公司/字典 | 拒绝并提示「已存在同名…，请更换名称」 |
| E-15 | 车头/挂车需求子列表为空 | 列表「车头数量/挂车数量」显示 0；保存允许（可后续补充） |
| E-16 | 子列表数量为负 | 前端 `number` 校验 + 后端 `qty` 非负约束，负值时 422 |
| E-17 | 车辆型号下拉取不到枚举 | 字典被清空时下拉为空，保存时车型可为空字符串，不阻断项目保存 |
| E-18 | 并发编辑同一条数据 | 后写覆盖先写，并在操作日志中留痕 |
| E-19 | 大数据量聚合 | 聚合在数据库层完成，页面响应不超过 2 秒 |
| E-20 | 空数据 | 无指标数据的组织进入驾驶舱显示「本周期暂无指标数据」空态，不报错不显示 NaN/undefined |
| E-21 | 服务不可用 | 前端请求失败时给出明确错误提示，不出现白屏 |

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 技术栈（实际） | 后端 Python 3.13 + FastAPI + SQLAlchemy 2.0 + Pydantic v2（SQLite 单文件库；可切换 PostgreSQL）；前端 Vue 3 + TypeScript + Vite + Tailwind + Pinia |
| 性能 | 单页首屏 ≤ 3 秒（内网）；列表接口 P95 ≤ 500ms；聚合接口 P95 ≤ 2 秒 |
| 并发 | 支持 200 个在线用户、峰值 50 QPS（一期规模） |
| 兼容性 | Chrome / Edge / Safari 最新两个大版本；最小可用宽度 1024px；1920×1080 投屏为基准 |
| 安全 | 密码加盐哈希存储（不可逆）；JWT 令牌鉴权（Cookie + Bearer 双支持，网关重写 Authorization 时 Cookie 兜底）；权限在服务端强制校验；敏感配置走环境变量 |
| 可用性 | 部署为单端口同源托管（后端启动自动建表 + 种子）；支持多实例水平扩展（无状态鉴权） |
| 可维护性 | 配置外置；数据字典等配置在线维护，避免改代码 |
| 可追溯 | 关键写操作（录入、修改、导入、删除）留操作日志，含操作人、时间、目标对象 |
| 国际化 | 一期仅简体中文 |

## 10. 明确不做的事情

| 编号 | 不做 | 说明 |
|---|---|---|
| N-1 | 异常归因闭环填报 | 看板只**提示**风险，不**跟踪**整改过程与闭环状态 |
| N-2 | 财务核算、薪酬计算 | 由财务系统承担 |
| N-3 | 甘特图、跨部门资源排期、工时管理 | 项目管理范畴，本期不做 |
| N-4 | 自由拖拽式 BI 报表引擎 | 指标与布局固定，不做自助拖拽 |
| N-5 | 审批流引擎 | 指标录入即生效，无审核环节 |
| N-6 | 移动端 App | 仅做响应式 Web |
| N-7 | 与业务系统直连取数 | 一期仅手工填报 + Excel 导入 |
| N-8 | 多租户 / 多语言 | 单公司部署，仅简体中文 |
| N-9 | 指标录入的版本对比与回滚 | 仅保留历史周期数据，不做版本回滚 |
| N-10 | 邮件/短信/IM 通知 | 本期不做消息推送 |
| N-11 | 车辆需求独立建模为资产台账 | 车头/挂车需求仅作为项目商机属性，不做资产全生命周期管理 |

## 11. 验收标准

> 每条给出「操作步骤 → 预期结果」，可手工执行验证。

### 11.1 登录与权限

| 编号 | 步骤 | 预期结果 |

| AC-01 | 用管理员账号登录 | 进入驾驶舱，侧边栏出现菜单（驾驶舱/任务/项目/指标/账号/系统配置） |

| AC-05 | 登出后刷新页面 | 回到登录页，需要重新登录 |
| AC-06 | 停用账号后登录 | 提示「账号已停用」 |
