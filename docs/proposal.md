# 合一重卡生态经营看板 · 产品需求说明（proposal）

> 版本：v1.0 · 2026-10-10
> 状态：待评审
> 依据：原型 `经营看板/`（已通过 6 轮改造验证）+ 已锁定决策基线
> 说明：本文回答「做什么、为什么、做到什么程度」，不含技术实现细节。技术方案见 `design.md`。

---

## 1. 项目背景

合一重卡生态是围绕新能源重卡展开的「销售 — 运力 — 补能 — 租赁」一体化业务，由一家总部（全公司）统一管理，下设市场、资产、运营、补能、技术支持、财务、金融、行政、人事、数智化、法务共 11 个二级部门，另有 3 家独立核算的项目运营公司（重卡运营、补能运营、车辆租赁）。

当前经营数据分散在各部门台账与临时表格中，月度经营会前由人工汇总，存在三个直接后果：口径不统一、汇总滞后、责任无法追溯到组织与个人。本项目旨在建立一个由总部统一承载、按组织与角色分权使用的经营看板系统，把「目标下达 — 数据填报 — 达成判定 — 风险提示」固化为线上闭环。

项目已完成高保真原型（零依赖单页应用）并经过 6 轮业务确认，交互与口径已锁定。本阶段目标是把原型升级为**前后端分离、可正式部署的生产级系统**。

---

## 2. 要解决的问题

| 编号 | 问题 | 现状 | 期望 |
|---|---|---|---|
| P-1 | 口径不统一 | 各部门各算各的，同一指标出现多个版本 | 指标口径、单位、方向、阈值在系统内唯一定义，全公司共用 |
| P-2 | 汇总滞后 | 月度经营会前人工拉表，1~2 天出不来 | 线上填报即生效，看板实时聚合 |
| P-3 | 责任不清晰 | 指标缺口说不清该谁负责 | 每个指标、每项任务绑定责任组织与责任人，缺口可下钻定位 |
| P-4 | 权限无隔离 | 全员共用一套账号，谁都能看全公司数据 | 按组织与角色分权，可见范围与可操作按钮双重管控 |
| P-5 | 组织无法维护 | 部门、项目公司调整要改代码 | 部门与项目公司支持在线增删改，任务与指标自动跟随 |
| P-6 | 风险靠人盯 | 逾期、异常、未达标指标靠人记 | 系统按规则自动判定红黄绿灯、临期逾期，并生成结论文案 |

## 3. 目标用户

| 角色 | 典型人员 | 使用场景 | 关注点 |
|---|---|---|---|
| 系统管理员 | 陈志明（数智化/运营负责人） | 维护组织与账号、配置角色权限、管理指标口径 | 全公司数据可控、账号安全 |
| 部门负责人 | 王建国（财务）、林雪（市场）等 11 人 | 查看本部门及下属部门任务与指标、录入数据 | 本部门达成情况、缺口与风险 |
| 普通成员 | 郑凯、何欣等 | 维护指派给自己的任务、录入本人指标 | 本人任务进度、是否临期逾期 |
| 项目公司负责人 | 李强（重卡运营）、周敏（补能）、高翔（租赁） | 维护本公司运营车辆/收入/回款/利润 | 本公司经营指标达成 |

使用环境：PC 浏览器（Chrome / Edge / Safari 最新两个大版本），会议室投屏（1920×1080）与办公本（1366×768）为主，窄屏（≥1024px）可用。

## 4. 核心目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-1 | 月度数据一次填报、全员同源可见 | 指标录入保存后，驾驶舱与维护页读数一致，无二次汇总 |
| G-2 | 达成判定与风险提示自动化 | 红黄绿灯、临期/逾期、分析总结全部由系统按规则生成，零人工判断 |
| G-3 | 数据按组织与角色严格隔离 | 任一角色登录后不可见越权组织的数据，且不可操作无权限按钮 |
| G-4 | 组织与账号可自助维护 | 部门、项目公司、账号、角色的增删改全部在线完成，无需改代码 |
| G-5 | 系统可正式部署 | 提供 Docker 一键启动（数据库 + 后端 + 前端 + 反向代理），支持环境变量外置 |

## 5. MVP 功能范围

### 5.1 登录与会话（AUTH）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| A-1 | 账号 + 密码登录 | 正确凭据进入系统；错误凭据提示「账号或密码错误」且不泄露账号是否存在 |
| A-2 | 登录态保持与登出 | 刷新页面保持登录；登出后回到登录页且本地凭据清除 |
| A-3 | 登录记录 | 记录每次登录的时间与 IP，管理员可在账号页查看最近登录时间 |
| A-4 | 停用账号限制 | 状态为「停用」的账号登录被拒绝并提示 |

### 5.2 组织管理（ORG）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| O-1 | 组织树展示 | 以「全公司 → 二级部门 → 子部门」层级展示，默认全展开可见层级缩进 |
| O-2 | 部门新增/编辑 | 可在全公司下新增二级部门，可在任意部门下创建子部门，可改名称与负责人 |
| O-3 | 部门删除约束 | 部门下有账号时禁止删除（仅可修改）并给出原因；部门有下级部门时禁止删除 |
| O-4 | 项目公司维护入口分离 | 项目公司不在组织树内维护，新增/编辑/删除统一在「指标维护」页完成；从组织页移除新增项目公司入口 |
| O-5 | 部门调色与任务跟随 | 删除部门时，该部门下任务自动上移至其上级部门，不产生无归属数据 |

### 5.3 角色与权限（ROLE）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| R-1 | 角色列表与查询 | 列表展示角色名称、说明、数据可见范围、关联账号数，支持按名称搜索 |
| R-2 | 角色新增/编辑 | 编辑界面可勾选「菜单权限」与「按钮权限」，可设置数据可见范围四类之一 |
| R-3 | 菜单权限联动 | 取消父级菜单权限时，其下按钮权限自动取消勾选 |
| R-4 | 角色删除约束 | 内置角色（系统管理员/部门负责人/普通成员）不可删除；角色下有账号时不可删除 |

### 5.4 账号管理（ACCOUNT）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| U-1 | 账号列表与查询 | 展示姓名、账号、所属部门、角色、状态、最近登录，支持搜索与筛选 |
| U-2 | 账号新增/编辑 | 可设置姓名、账号、初始密码、所属部门、角色、状态 |
| U-3 | 所属部门取值范围 | 部门选项与组织管理一致（全公司 + 各部门层级缩进），不含项目公司 |
| U-4 | 数据可见范围 | 可选「跟随角色默认 / 本人 / 本部门 / 本部门及下属部门 / 全公司」，账号值可覆盖角色默认值 |
| U-5 | 启停用 | 可停用/启用账号；停用后不可登录 |

### 5.5 指标维护（METRIC）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| M-1 | 指标三组结构 | 维护页纵向排列三模块：①公司整体目标 ②指标监控 ③项目公司指标 |
| M-2 | 指标口径唯一定义 | 每个指标含编码、名称、单位、方向、所属组、权重、责任部门、口径说明 |
| M-3 | 录入即生效 | 录入年度目标/完成值/回款，保存后立即影响驾驶舱读数，无审核环节 |
| M-4 | 年度目标按年度存储 | 年度目标与项目公司目标按「年份」存一份，全年各月度周期共用；修改任一周期即改年度目标 |
| M-5 | 完成率口径 | 完成率 = 累计完成 / 年度目标；收入/消化/利润为**年初至今累计**，运营车辆为**期末快照** |
| M-6 | 回款口径 | 回款率 = 累计回款 / 累计收入完成值；目标回款率默认 95%（项目公司 93%），≥目标绿、低 5 个百分点内黄、其余红 |
| M-7 | 时间进度对比 | 展示年度时间进度（按数据截至日计算）与「完成率 vs 时间进度」差值，正数表示跑赢时间轴 |
| M-8 | 监控指标 | 事故/故障/租金减免等 10 项监控指标无目标值、无红黄绿灯，仅统计展示当月快照 |
| M-9 | 项目公司列表化增删 | 项目公司模块以列表呈现，每公司一行含目标/完成行内录入、完成率、达成徽标、保存/编辑/删除；支持新增项目公司 |
| M-10 | 项目公司删除影响面 | 删除项目公司前提示影响面（目标数/完成值数/任务数/账号数）；删除后连带清理其指标数据、任务，关联账号停用 |
| M-11 | 与驾驶舱联动定位 | 驾驶舱点「去维护」可定位到对应指标行并高亮；维护页可「查看驾驶舱」返回 |
| M-12 | 指标批量导入 | 按标准模板导入实际值，逐行校验，错误行高亮并列出「行号 + 字段 + 错误说明」 |

### 5.6 任务管理（TASK）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| T-1 | 任务列表字段 | 列含：任务ID、任务名称、任务分类、责任人、责任部门、目标、已完成、完成进度、起止日期、状态、操作 |
| T-2 | 冻结列与横滑 | 表格超宽时左右滑动，任务ID/任务名称冻结在左、操作列冻结在右 |
| T-3 | 任务新增/编辑 | 新建弹窗字段与列表一致（任务名称=一级任务，任务分类=二级任务）+ 描述、是否异常、目标、已完成、单位、进展描述、起止日期、责任部门、责任人 |
| T-4 | 完成进度自动计算 | 完成进度 = 已完成 / 目标（非量化任务目标填 1，未完成填 0、完成填 1），不接受手填百分比 |
| T-5 | 临期/逾期自动判定 | 剩余天数 = 计划结束日期 − 今天；≥1 天正常、0≤剩余<1 天临期、<0 天逾期；已完成任务不再判逾期 |
| T-6 | 任务健康度 | 时间判定叠加人工「是否异常」标记；异常且未完成显示「异常」 |
| T-7 | 任务筛选 | 支持按关键字、责任部门、状态筛选 |
| T-8 | 任务批量导入 | 按标准模板（11 填写列）导入，逐行校验；一级任务相同的多行自动归组为同一公司级任务 |

### 5.7 经营驾驶舱（DASH）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| D-1 | 规则生成分析总结 | 顶部展示「整体结论 + 亮点 + 风险 + 建议」，由确定性模板拼装，不引入 AI |
| D-2 | 整体结论含加权达成率 | 显示综合加权达成率、达标/接近/未达标项数、年度时间进度及跑赢/落后说明 |
| D-3 | 核心指标卡片 | 年度目标以卡片展示，收入类卡片含回款行；卡片显示目标/完成/完成率/状态与时间进度对比 |
| D-4 | 项目公司对比区 | 公司视角展示 3 家项目公司的运营车辆/运营收入/回款/利润对比，每行可「去维护」 |
| D-5 | 监控指标区 | 展示事故/故障/租金减免当月亮化数据 |
| D-6 | 部门任务完成度 | 按部门展示任务完成统计卡（任务数/已完成/逾期/异常），有风险的任务卡红边并优先排序 |
| D-7 | 风险与异常清单 | 汇总红灯指标、环比走弱指标、不健康任务，置于页面文末，点击可定位到对应指标/任务 |
| D-8 | 指标下钻 | 点击指标卡可查看趋势与下级拆解 |

### 5.8 数据导入（IMPORT）

| 编号 | 需求 | 可验证点 |
|---|---|---|
| I-1 | 标准模板下载 | 提供任务导入模板（11 填写列）与指标导入模板 |
| I-2 | 逐行校验 | 错误行高亮，列出「行号 + 字段 + 错误说明」 |
| I-3 | 原子性 | 存在错误行时仅导入通过校验的行，或整体拒绝，绝不部分写入脏数据 |
| I-4 | 任务校验规则 | 至少覆盖：一级任务为空、是否异常取值非法、目标非正数、已完成为负、日期格式错误、结束早于开始、责任部门不存在、责任人非系统账号（共 8 类） |

## 6. 用户操作流程

### 流程一 · 管理员初始化

```
登录（管理员）→ 账号管理 · 组织结构（确认 11 个二级部门）→ 角色权限（配置各角色菜单与按钮权限）
→ 账号管理（新增账号、设定所属部门与可见范围）→ 指标维护（设定年度目标与项目公司目标）
→ 任务管理（导入或新建重点任务）→ 通知各部门开始填报
```

### 流程二 · 部门/成员月度填报

```
登录 → 指标维护（录入本部门/本人指标完成值、回款）→ 保存（立即生效）
→ 任务管理（更新「已完成」、进展描述、是否异常）→ 驾驶舱确认本部门读数正确
```

### 流程三 · 项目公司负责人填报

```
登录（项目公司负责人）→ 指标维护（仅见本公司行）→ 录入运营车辆（期末快照）/运营收入/回款/运营利润
→ 保存 → 驾驶舱查看本公司对比位置
```

### 流程四 · 月度经营会

```
登录（管理员）→ 经营驾驶舱 → 阅读分析总结（结论/亮点/风险/建议）
→ 点风险条目定位到指标或任务 → 去维护页修正数据 → 返回驾驶舱复核
```

## 7. 输入和输出

### 输入

| 来源 | 内容 | 约束 |
|---|---|---|
| 页面录入 | 指标年度目标、完成值、回款；任务字段 | 数字字段必须为有效数字；日期必须 `YYYY-MM-DD` |
| Excel 导入 | 任务批量数据（11 列）、指标实际值（5 列） | 必须使用系统提供模板；列名不可自改 |
| 组织/账号维护 | 部门、项目公司、账号、角色 | 名称不可重复；删除受约束规则限制 |

### 输出

| 输出 | 形式 | 说明 |
|---|---|---|
| 经营驾驶舱 | 页面 | 分析总结 + 核心指标卡 + 项目公司对比 + 监控指标 + 部门任务完成度 + 风险清单 |
| 指标维护页 | 页面 | 三模块录入表，含实时完成率与状态 |
| 任务管理页 | 页面 + 可导出 Excel | 任务列表与详情 |
| 账号/组织/角色 | 页面 | 管理界面 |
| 操作日志 | 数据留痕 | 记录录入、修改、导入、登录操作 |

## 8. 异常场景

| 编号 | 场景 | 期望行为 |
|---|---|---|
| E-1 | 账号或密码错误 | 提示「账号或密码错误」，不区分账号不存在与密码错误 |
| E-2 | 账号被停用 | 登录被拒，提示「账号已停用，请联系管理员」 |
| E-3 | 登录态过期 | 请求返回未授权时，自动跳转登录页并提示「登录已过期，请重新登录」 |
| E-4 | 无权限访问页面/按钮 | 侧边栏不出现无权限菜单；直接访问受限页面显示无权限提示；无权限按钮不渲染 |
| E-5 | 越权访问数据 | 后端按可见范围强制过滤，即使前端构造请求也拿不到越权数据 |
| E-6 | 目标值为 0 | 按绝对值判定，不套用比率，不出现除零 |
| E-7 | 实际值缺失 | 达成率显示「—」，状态为「未录入」，不参与加权统计 |
| E-8 | 收入为 0 时算回款率 | 回款率显示「—」，不出现除零或 Infinity 展示异常 |
| E-9 | 逆向指标实际值为 0 | 视为达标（如零事故），达成率按达标处理 |
| E-10 | Excel 行数据非法 | 该行不进库，整批高亮错误行并列出错误明细 |
| E-11 | Excel 责任人/部门不存在 | 报错「不是系统内已有账号姓名 / 不是有效的组织名称或编码」 |
| E-12 | Excel 指标周期与看板周期不一致 | 报错「与当前看板周期不一致」，整行拒绝 |
| E-13 | 删除有账号的部门 | 拒绝并说明「该部门下有 N 个账号，不允许删除，仅可修改」 |
| E-14 | 删除有账号的角色 | 拒绝并说明「该角色下仍有 N 个账号，请先调整这些账号的角色」 |
| E-15 | 重名组织/角色/项目公司 | 拒绝并提示「已存在同名…，请更换名称」 |
| E-16 | 删除项目公司 | 二次确认并展示影响面，确认后连带清理并停用关联账号 |
| E-17 | 并发编辑同一条数据 | 后写覆盖先写，并在操作日志中留痕（本期不做乐观锁冲突提示） |
| E-18 | 大数据量聚合 | 上千行数据聚合必须在数据库层完成，页面响应不超过 2 秒 |
| E-19 | 空数据 | 无指标数据的组织进入驾驶舱显示「本周期暂无指标数据」空态，不报错不显示 NaN/undefined |
| E-20 | 服务不可用 | 前端请求失败时给出明确错误提示，不出现白屏 |

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 单页首屏 ≤ 3 秒（内网）；列表接口 P95 ≤ 500ms；聚合接口 P95 ≤ 2 秒（万级数据量） |

### 12.3 2026-10-12 · 第三批变更

#### M-16 统计周期组件交互优化

- **背景**：原实现用原生 `<input type="month">`。该类型 **Safari 不支持**，会退化成普通文本框；
  样式也无法与系统统一。且可选跨度达 73 年（2026-09 ~ 2099-12），原生控件只能逐月 / 逐年切换。
- **需求**：参考主流月份选择组件重做交互。
- **验收标准**
  1. 触发器显示「YYYY年M月」并带图标，不再是原生输入框；
  2. 点击展开面板，3×4 网格展示 12 个月，选中项主色填充；
  3. 点年份标题切到年份面板，按 12 年翻页，可快速到达 2099；
  4. 越界月份 / 年份禁用（下界 2026-09 之前、上限 2099-12 之后）；
  5. 点击面板外部或按 Esc 关闭；选中后自动关闭并同步触发器；
  6. 页面中不再存在原生 `type=month` 输入框。

#### M-17 项目公司允许删除

- **背景**：项目公司的增 / 改 / 删入口原本挂在「具备公司整体目标权限 **且** 当前视角为全公司」上。
  结果是：仅持有「维护项目公司指标」权限的角色、或把组织视角切到项目公司时，**入口直接消失、无法操作**；
  与「所有操作只看权限是否覆盖，不写死角色与视角」的既定原则不一致。
  另外，删除项目公司后，其关联账号的部门归属会指向已不存在的组织（悬空引用）。
- **需求**
  - 新增独立权限点 `project.create` / `project.edit` / `project.delete`，前端入口与后端接口均按权限点判定；
  - 内置角色同步，权限可在「账号管理 → 角色权限」按需勾选；
  - 删除时清理悬空引用：子组织上移到上级组织，关联账号停用并迁移到上级组织。
- **验收标准**
  1. 权限目录出现三个新权限项，系统管理员默认具备；
  2. 仅持有 `metric.edit_project` 的角色调用增 / 改 / 删接口返回 403；
  3. 自定义角色勾选对应权限后即可完成操作（能力与角色标识无关）；
  4. 全公司视角与项目公司视角下，删除 / 编辑入口均可见；
  5. 删除后全库不存在指向已删除组织的 `dept_id` / `parent_id`。

  另外分组视图的部门标题会随内容一起滚出视口。
- **需求**
  - 冻结列之间的间隙改为纯色、不透出下层内容；
  - 分组视图下横向滚动时，部门标题与统计数字位置固定，仅列表内容滚动。
- **验收标准**：滚动前后两列边缘严丝合缝（差值 < 1px）；滚动后部门标题仍停留在容器左侧。

#### P-1 加载性能优化

- **背景**：排查发现静态资源**既未压缩也无缓存头**——169.73 KB 的主包原样传输，且每次访问都完整重下；
  任务列表接口则是「先全量查出、再在内存里切片」，分页并未真正减少数据读取。
- **需求**：优化加载速度。
- **验收标准**
  1. JS / CSS 与 JSON 响应启用 gzip（主包体积降至约 38%）；
  2. 带内容哈希的构建产物设置长期强缓存，`index.html` 不缓存；
  3. 任务列表分页与状态过滤下推到 SQL，只读取当前页。
