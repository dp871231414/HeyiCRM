# 合一重卡生态经营看板 · 产品需求说明（proposal）

> 版本：v3.2 · 2026-10-17
> 状态：已评审 · 当前实现基线
> 说明：本版相对 v2.0 做了结构性重写——**不再按模块罗列功能点，而是按「用户实际操作路径」组织需求，并在文末集中给出字段规则表**。业务规则（完成率/回款率/红黄绿灯/汇总口径/数据权限）从各处的零散描述抽离到 §4 统一说明，便于评审时核对"逻辑是否自洽"。v3.1 新增「下载中心」（导出先生成记录再下载），并去掉「典型人员」列（虚拟角色名会让真实用户困惑）。**v3.2 调整导出口径：导出不再即时返回文件供本地下载，只在「下载中心」生成一条导出记录并把文件落盘，由用户在下载中心点击「下载」获取；同时从「项目管理」移除「重新生成」功能（不再提供整库种子数据重建入口）。**
> 关联文档：技术方案见 `design.md`，测试结论见 `test-report.md`。需求编号（A/O/R/U/M/T/D/K/S/I）保留为可追溯锚点，散见于各路径步骤中。

## 1. 文档定位与阅读指引

- **写给谁**：实施方（开发/测试）、评审方（业务负责人）、后续接手的产品/运维。
- **怎么读**：先读 §2（背景与目标）、§2.4（角色权限基线）建立"谁用什么"的全局认识；再看 §3 的五大操作路径，理解系统在真实业务里怎么被用起来；§4 是判断口径的"规矩总闸"；§5 是查字段的字典；§6–§10 是边界、验收与非功能约束。
- **与老版差异**：v2.0 把功能拆成 A-1…I-6 的表格逐条列，适合"查有没有"，但不易看出"为什么这么串、字段怎么填"。本版把同一批需求嵌回业务流程，并补字段规则，避免流水账。

## 2. 业务背景与核心目标

### 2.1 背景

合一重卡生态围绕新能源重卡做"销售—运力—补能—租赁"一体化经营，由一家总部统一管理 11 个二级部门 + 3 家独立核算的项目运营公司。经营数据原本散在各部门台账与临时表格，月度经营会前靠人工汇总，带来三个直接后果：**口径不统一、汇总滞后、责任无法追溯到组织与个人**。本系统把"目标下达—数据填报—达成判定—风险提示"固化为线上闭环。

### 2.2 要解决的问题

| 编号 | 问题 | 期望 |
|---|---|---|
| P-1 | 口径不统一 | 指标口径/单位/方向/阈值系统内唯一定义，全公司共用 |
| P-2 | 汇总滞后 | 填报即生效，看板实时聚合，无需二次拉表 |
| P-3 | 责任不清晰 | 指标/任务绑定责任组织与责任人，缺口可下钻 |
| P-4 | 权限无隔离 | 按组织与角色分权，可见范围与可操作按钮双重管控 |
| P-5 | 组织无法维护 | 部门/项目公司在线增删改，任务与指标自动跟随 |
| P-6 | 风险靠人盯 | 系统按规则自动判红黄绿灯、临期逾期并生成结论文案 |
| P-7 | 车辆需求缺结构化 | 车头/挂车需求以可增删子列表录入，列表展示汇总，明细可追溯 |
| P-8 | 车型无统一来源 | 车辆/挂车型号由数据字典维护，表单下拉取值 |
| P-9 | 导入模板过重 | 项目导入只填项目信息，车辆需求在系统内补充 |

### 2.3 核心目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-1 | 数据一次填报、全员同源可见 | 指标保存后驾驶舱与维护页读数一致，无二次汇总 |
| G-2 | 达成判定与风险提示自动化 | 红黄绿灯、临期逾期、分析总结全部系统按规则生成，零人工判断 |
| G-3 | 数据按组织与角色严格隔离 | 任一角色登录后不可见越权数据、不可操作无权限按钮 |
| G-4 | 组织与账号可自助维护 | 部门/项目公司/账号/角色增删改全在线，无需改代码 |
| G-5 | 可正式部署 | 单端口同源托管，配置外置，数据字典等在线维护 |
| G-6 | 车辆需求结构化、车型可配置 | 车头/挂车需求子列表录入并展示汇总；车型由数据字典统一维护 |

### 2.4 角色与权限基线（who + 权限模型）

**四类角色**（内置角色不可删，可由 `account.role` 权限者调整）：

| 角色 | 关注点 | 默认数据可见范围 |
|---|---|---|
| 系统管理员 | 全公司数据可控、账号安全 | 全公司 |
| 部门负责人 | 本部门达成、缺口风险 | 本部门及下属部门 |
| 普通成员 | 本人任务进度、是否临期 | 本人 |
| 项目公司负责人 | 本公司经营指标 | 本部门及下属部门 |

**权限模型**：菜单权限（`.view`，控制菜单/页面是否可见）+ 按钮权限（`.edit`/`.import`/`.delete` 等，控制页面内操作是否可渲染/可执行）。**数据可见范围**四类：`self` 本人 / `dept` 本部门 / `dept_sub` 本部门及下属部门 / `all` 全公司。账号可单独覆盖角色默认范围。

**默认权限**：所有角色自动获得 `task.detail`、`market.detail`、`sys.config.view`、`download.view`（保证车型下拉等基础可读、下载中心默认可见）。侧边栏按菜单权限过滤，无权限按钮不渲染；后端对所有写操作强制按权限 + 可见范围二次校验，前端构造越权请求也拿不到数据。

## 3. 核心操作流程（用户视角）

每个路径给出：**谁** → **在哪个页面** → **步骤** → **关键规则 / 字段**（字段细节见 §5，业务口径见 §4）。

### 路径一 · 系统初始化（管理员首次部署）

目标：把"空系统"变成"可填报状态"。

**3.1 搭建组织与部门** — 页面「账号管理 → 组织结构」`[O-1~O-5]`
1. 组织树以「全公司(CO) → 二级部门 → 子部门」层级展示，默认全展开。
2. 在 CO 下新增二级部门（如市场部 D01），或任一部门下建子部门；可改名称与负责人。
3. 删除约束：部门下有账号、或有下级部门时禁止删除，仅可修改（`[O-3]`）。
4. 删除部门时，其下属任务自动上移至上级部门，不产生无归属数据（`[O-5]`）。
5. 项目公司（独立核算）**不在组织树维护**，统一在「指标维护 → 项目公司指标」增删（`[O-4]`）。

**3.2 配置角色与权限** — 页面「账号管理 → 角色权限」`[R-1~R-4]`
1. 角色列表展示名称/说明/数据可见范围/关联账号数，支持按名搜索。
2. 编辑界面勾选「菜单权限」与「按钮权限」，并设置数据可见范围之一。
3. 取消父级菜单权限时，其下按钮权限自动取消勾选（`[R-3]`）。
4. 内置角色（系统管理员/部门负责人/普通成员）不可删；角色下有账号时不可删（`[R-4]`）。

**3.3 开通账号** — 页面「账号管理 → 账号」`[U-1~U-6]`
1. 列表展示姓名/账号/所属部门/角色/状态/最近登录，支持搜索筛选。
2. 新增/编辑：姓名、账号、初始密码、所属部门（选项与组织树一致，不含项目公司）、角色、状态。
3. 数据可见范围可选「跟随角色默认 / 本人 / 本部门 / 本部门及下属部门 / 全公司」，账号值可覆盖角色默认。
4. 启停用：停用后不可登录。
5. 批量导入/删除：按模板导入（任一行错误整批不写）；仅当账号未被任何数据引用时可删。

**3.4 维护数据字典（车型等）** — 页面「系统配置 → 数据字典」`[S-1~S-6]`
1. 系统配置为一级菜单，可见性受 `sys.config.view` 控制；新增/编辑/删除需 `sys.config.edit`。
2. 字典以 `code` 为稳定标识（如 `vehicle_model`/`trailer_model`），前端下拉按 code 取值。
3. 种子预设：车辆型号（6*4牵引车、4*2牵引车、矿卡、自卸车）、挂车型号（侧翻挂、高栏挂、后翻挂），可后续修改。
4. 所有角色默认有 `sys.config.view` → 项目管理表单的车型下拉能正常加载枚举。

**3.5 设定指标年度目标** — 页面「指标维护 → 公司整体目标 / 项目公司指标」`[M-1~M-4]`
1. 维护页纵向三模块：①公司整体目标 ②指标监控 ③项目公司指标。
2. 指标定义含编码/名称/单位/方向/所属组/权重/责任部门/口径说明（由管理员在后台固化，非业务方日常填）。
3. 录入年度目标/完成值/回款，保存后立即影响驾驶舱读数，无审核环节（`[M-3]`）。
4. 年度目标按"年份"存一份，全年各月度周期共用（`[M-4]`）。

### 路径二 · 月度经营填报（部门负责人 / 成员）

目标：每月把本部门/本人指标与任务进度填进系统。

**3.6 录入指标完成值与回款** — 页面「指标维护」`[M-5~M-7]`
1. 部门负责人在「指标监控」录入本部门指标的当月完成值；项目公司负责人在「项目公司指标」录入运营车辆/收入/回款/利润。
2. 收入/消化/利润为**年初至今累计**（填至数据截至月），运营车辆为**期末快照**（填当月在册数）。
3. 系统实时算完成率（=累计完成/年度目标）与回款率（=累计回款/累计收入），并展示时间进度对比（口径见 §4.1–§4.2）。
4. 监控指标（事故/故障/租金减免等 10 项）无目标值、无灯，仅填当月快照（`[M-8]`）。

**3.7 更新任务进度** — 页面「任务管理」`[T-1~T-7]`
1. 任务列表超宽时左右滑动，任务ID/主任务/任务名称冻结在左、操作列冻结在右。
2. 编辑任务：更新「已完成」、进展描述、是否异常、起止日期、责任部门、责任人。
3. 完成进度 = 已完成/目标，**不接受手填百分比**（系统算，`[T-4]`）。
4. 系统按计划结束日期自动判临期/逾期（已完成任务不再判，`[T-5]`），叠加人工「是否异常」得健康度（`[T-6]`）。
5. 支持按关键字/责任部门/状态筛选（`[T-7]`）。

**3.8 追加任务进展时间轴** — 页面「任务管理 → 任务详情」`[T-10]`
1. 任务进展以时间轴记录，可追加；编辑任务不可直改进展，只能追加新记录。
2. 每条进展独立保留，列表「进展描述」列展示最新一条（冗余快照）。

### 路径三 · 商机（市场项目）管理（含车头/挂车需求子列表）

目标：管理销售线索/商机，按阶段推进，并结构化为后续排产提供车头/挂车需求。

**3.9 新建/编辑项目并录入车辆需求** — 页面「项目管理」`[K-1~K-7, I-5]`
1. 新建项目：填项目名称、项目进展（必填，写入第一条进展）、项目描述、项目阶段（固定 10/25/50/75/90/100）、负责人、所属部门。
2. **车头需求**以表格录入（`[K-1]`）：列头直接展示「车辆型号 / 电池度数 / 数量 / 操作」；每行车辆型号为下拉（取自数据字典 `vehicle_model`），电池度数、数量为输入框；可「+ 添加一行」、可删行。
3. **挂车需求**同理（`[K-2]`），挂车型号下拉取自 `trailer_model`。
4. 车辆需求**不进导入模板**（`[I-5]`）：项目导入只填 6 列（项目名称/项目进展/项目描述/项目阶段/负责人/所属部门），车辆需求在系统内补充。
5. 保存后，列表「车头数量 / 挂车数量」列展示各明细行数量**汇总值**（`[K-3]`），详情展示明细（`[K-5]`）。
6. 驾驶舱漏斗读车头/挂车需求**汇总值**，子列表改造不影响驾驶舱口径（`[K-4]/§4.6`）。

**3.10 查看项目详情与进展时间轴** — 页面「项目管理 → 项目详情」
1. 详情只读展示：项目信息 + 车头/挂车需求明细行（车型+电池+数量）+ 项目进展时间轴。
2. 进展时间轴同任务：只能「新增进展」追加，不可直改历史记录。

### 路径四 · 经营驾驶舱复盘（管理层经营会）

目标：一页看清全公司达成、风险与商机漏斗。

**3.11 驾驶舱各区块逻辑** — 页面「经营驾驶舱」`[D-1~D-9]`
1. 顶部「分析总结」= 整体结论 + 亮点 + 风险 + 建议，由确定性模板拼装（不引入 AI，`[D-1]`）。
2. 整体结论含**加权达成率**（按指标权重）、达标/接近/未达标项数、年度时间进度及跑赢/落后说明（`[D-2]`）。
3. 核心指标卡片：年度目标以卡展示，收入类含回款行；卡片显示目标/完成/完成率/状态 + 时间进度对比（`[D-3]`，口径见 §4.3）。
4. 项目公司对比区：3 家项目公司的运营车辆/收入/回款/利润对比，每行可「去维护」跳维护页（`[D-4]`）。
5. 监控指标区：事故/故障/租金减免当月亮化数据（`[D-5]`）。
6. 部门任务完成度：按部门统计任务数/已完成/逾期/异常，支持口径筛选（全部/本年新增/当月新增/未结束，`[D-6]`）。
7. 风险与异常清单：汇总红灯指标、环比走弱指标、不健康任务，点击可定位（`[D-7]`）。
8. 市场项目概览：项目转化漏斗 + 车辆/挂车需求漏斗（当前阶段口径）+ 销量预测（按阶段转化概率加权，`[D-8]`）。漏斗读汇总值，口径稳定（`[D-9]/§4.6`）。

### 路径五 · 持续运营配置

**3.12 数据字典与漏斗概率维护** — 页面「系统配置」「驾驶舱配置」
1. 数据字典：新增/编辑（枚举值整份替换、可增删多行）/删除；名称、编码、枚举值均可在系统内改，无需改代码（`[S-6]`）。
2. 漏斗转化概率：各阶段配置转化概率（0~1），缺省按阶段百分比回落；整车需求漏斗与销量预测共用（`[D-8]`）。

**3.13 下载中心（导出记录的查看与再下载）** — 菜单「下载中心」`[X-1~X-6]`
1. 所有导出（任务清单、市场项目清单）点击「导出」后，**只在「下载中心」生成一条导出记录并把文件落盘，不再即时返回文件供本地下载**（`[X-2]`）；前端导出按钮点击后提示「已生成导出记录，请前往下载中心下载」并跳转到下载中心，由用户在那里点击「下载」获取文件。文件按「对象 + 时间」自动命名（如 `重点任务_20261017_091523.xlsx`），无需手工起名（`[X-3]`）。
2. 进入「下载中心」可见本人全部导出记录：导出记录ID、导出文件名称、对象（重点任务 / 市场项目）、创建人、创建时间（`[X-3]`）。
3. 对任一条记录可「下载」（按记录ID取文件，文件名即导出文件名称）或「删除」（记录与文件一并移除，`[X-4]/[X-5]`）。
4. 列表仅展示本人创建的记录；文件下载 / 删除仅创建人本人可操作，他人不可见也不可操作（`[X-6]`）。

## 4. 关键业务规则（逻辑总闸）

> 本节把分散在功能点里的"计算与判定"集中说明，确保前后口径一致。

### 4.1 指标口径与完成率
- 完成率 = 累计完成 / 年度目标。
- 收入/消化/利润类：完成值取**年初至今累计**；运营车辆类：完成值取**期末快照**。
- 目标值为 0：按绝对值判定，不套比率、不除零；实际值缺失：达成率显示「—」、状态「未录入」、不参与加权。
- 逆向指标（如事故）实际值为 0：视为达标。

### 4.2 回款率
- 回款率 = 累计回款 / 累计收入完成值；目标回款率默认 95%。
- ≥目标绿；低于目标但在 5 个百分点内黄；其余红。
- 收入为 0：回款率显示「—」，不出现除零/Infinity。

### 4.3 时间进度与红黄绿灯（状态判定）
- 时间进度 = 数据截至日 / 当年总天数（按年或所选周期）。
- 单指标状态 `progress_tone` = 完成率 ÷ 时间进度：`≥1` 绿、`[0.8,1)` 黄、`<0.8` 红；单指标与汇总统计共用同一判定，标签一致。
- 监控指标无目标、无灯，仅统计展示。

### 4.4 任务临期/逾期与健康度
- 剩余天数 = 计划结束日期 − 今天；`≥1` 天正常、`[0,1)` 天临期、`<0` 天逾期；已完成任务不再判逾期。
- 健康度 = 时间判定叠加人工「是否异常」：异常且未完成显示「异常」。

### 4.5 项目阶段与漏斗 / 销量预测
- 阶段固定 6 档：10 项目导入 / 25 市场尽调 / 50 初审通过 / 75 联合评审通过 / 90 签约落地 / 100 交车投运。
- 项目转化漏斗按各阶段项目数统计；销量预测 = Σ(阶段车辆需求 × 该阶段转化概率)。

### 4.6 车头/挂车需求汇总口径（一致性关键）
- 列表「车头数量」= 该项目车头需求各明细行 `qty` 之和；「挂车数量」同理。
- 该汇总值冗余存于 `market_project.tractor_demand / trailer_demand`，供驾驶舱漏斗直接复用。
- **子列表增删行 → 保存时后端重算汇总 → 列表与驾驶舱读数同步变化**，口径始终一致，无第二套来源。

### 4.7 数据权限过滤
- 所有列表/详情/聚合接口后端按账号的"有效可见范围"强制过滤：本人创建的项目始终可见；范围外读/改/删返回 403。
- 即使前端构造越权请求，也拿不到越权组织的数据。

| E-7 | 实际值缺失 | 达成率「—」、状态「未录入」、不加权 |
| E-8 | 收入为 0 算回款率 | 回款率「—」，不 Infinity |
| E-9 | 逆向指标实际值 0 | 视为达标 |
| E-10 | Excel 行非法 | 该行不进库，整批高亮错误行 |
| E-11 | Excel 责任人/部门不存在 | 报错「非系统内已有账号姓名 / 非有效组织名称或编码」 |
| E-12 | 删有账号的部门 | 拒绝并说明 |
| E-13 | 删有账号的角色 | 拒绝并说明 |
| E-14 | 重名组织/角色/项目公司/字典 | 拒绝并提示 |
| E-15 | 车头/挂车需求子表为空 | 列表数量显示 0，保存允许 |
| E-16 | 子表数量为负 | 前端 number 校验 + 后端 `qty≥0`，负 422 |
| E-17 | 车型下拉取不到枚举 | 字典被清空时下拉为空，车型可为空，不阻断保存 |
| E-18 | 并发编辑同一条 | 后写覆盖先写，操作日志留痕 |
| E-19 | 大数据量聚合 | 数据库层聚合，页面 ≤2s |
| E-20 | 空数据 | 显示空态，不报错不显 NaN |
| E-21 | 服务不可用 | 前端明确提示，不白屏 |
