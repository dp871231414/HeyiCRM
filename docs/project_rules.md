# AI 开发规则（project_rules）

> 本文件约束后续执行任务时的行为，不包含具体实现细节。

## 1. 任务范围控制
- 一次只执行 `tasks.md` 中编号明确的单个任务
- 不做任务范围外的「顺手优化」；发现新问题记录到 `tasks.md`，不直接修改
- 所有功能以 `proposal.md` 为准，不擅自扩展；文档缺失或不一致时先更新文档

## 2. 完成标准与验收
- 每个任务完成后，对照该任务「完成标准」逐项自检
- 汇报四项：修改了哪些文件 / 如何验证 / 验证结果 / 剩余风险
- 未通过验收不得进入下一任务

## 3. 异常与依赖处理
- 依赖冲突、需求不清晰时停止并提问，不自行猜测
- 不引入未确认的第三方依赖

## 4. 语言、框架与包管理
- 后端：Python 3.11 / FastAPI / SQLAlchemy 2.0 / Pydantic v2 / Alembic / PostgreSQL 15
- 前端：Vue 3 / TypeScript / Vite / Tailwind CSS / Pinia / Vue Router / Axios
- 包管理：后端 `pip` + `requirements.txt`（锁定版本）；前端 `npm`
- 新增依赖须先说明必要性并经确认

## 5. 目录结构与模块隔离
- 遵守 `design.md` §11 的目录结构
- 分层边界：API 只做参数/鉴权/组装；业务逻辑放 Service；持久化放 Model
- 模块间不得越界访问内部实现

## 6. 命名与代码风格
- 数据库：表名/字段名 `snake_case`；主键 `id`
- 后端：模块 `snake_case`，类 `PascalCase`，函数 `snake_case`
- 前端：组件文件 `PascalCase.vue`，组合式函数 `useXxx`，类型 `PascalCase`
- 接口路径：复数资源 + 小写连字符；统一前缀 `/api/v1`

## 7. 安全与隐私红线
- 密码必须加盐哈希存储，任何接口与日志不得返回 `password_hash`
- 数据库连接、JWT 密钥等敏感配置只走环境变量，禁止写入代码或提交到仓库
- 权限在服务端强制校验，前端隐藏不作为安全边界
- 所有查询必须按用户可见范围过滤，禁止越权返回数据
- `.env` 不提交；提供 `.env.example`

## 8. 文档同步
- 实现与文档不一致时，先更新文档并说明，再继续实现
- 接口变更必须同步更新 `design.md` §6 与前端 `types/`

## 9. Git 提交规则
- 每个任务验收通过后单独提交，只提交本任务相关文件
- 提交信息格式：`feat: complete T<编号> <任务名>`
- 不提交 `node_modules/`、`__pycache__/`、`.env`、构建产物
