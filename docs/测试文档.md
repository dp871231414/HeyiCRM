## 4. 关键测试用例（精选）

### 4.1 项目阶段可保存为「流失」(Round 34，test_changes.py)
- **用例**：新建/编辑项目 `stage=0` → 期望 200，`stageLabel=="流失"`；非法 `stage=33` → 422「项目阶段不合法」。
- **背景**：`_apply_payload` 原用 `MARKET_STAGE_VALUES`（不含 0）拦截流失，已改为 `ALL_PROJECT_STAGE_VALUES`。

### 4.2 车辆需求分析预估消化取整 (Round 35，test_demand_analysis.py)
- **用例**：`qty=10, stage=25(prob=0.25)` → digest 期望 `3`（10×0.25=2.5，half-up 取整而非 2）。
- **校验**：`isinstance(row["digest"], int)`；流失阶段 `stage=0` 计入总需求、digest=0。

### 4.3 数据字典启用/停用 (Round 31，test_system_dict.py)
- **用例**：删除接口 `DELETE /system/dicts/{id}` → 405；`POST .../status{status:"disabled"}` → 成功且 `status=="disabled"`；再切回 `active` 成功。
- **背景**：不允许删除已有配置，仅启停。

### 4.4 漏斗销量预测与阶段口径
- **用例**：三漏斗 `stages[]` 各阶段为当前数量口径不累计；`forecast` 四舍五入整数；部门筛选只统计该部门负责人名下项目。

### 4.5 文档中心接口测试 (`test_system_doc.py`, Round 36/37)
- 列表 `GET /system/docs`：返回 7 类内置文档（usage/prd/tech/test/visual/skill/devnotes），每条含渲染 `html` 与 `group` 字段。
- 分组映射：`usage.group=="用户文档"`，其余为「开发文档」。
- 获取/缺失：`GET /system/docs/prd` → 200；不存在 key → 404；**`design`（已合并入技术文档）→ 404**。
- 编辑渲染：PUT markdown 内容后 GET 返回含 `<h1>`/段落的 HTML；PUT html 内容原样返回。
- 同步：`POST /system/docs/sync` → 200 且 `synced` 为整数（幂等可用）。

### 4.6 文档中心分组与两级权限 (`test_system_doc.py`, Round 37)
- **分组字段**：列表/详情返回 `group`；编辑改 `group` 不影响 `doc_key`，且 `group` 变更不触发 `version+1`（仅 `content` 变更才 +1）。
- **新建文档**：`POST /system/docs` 省略 key 时后端自动生成 `doc_<8位hex>`；显式合法 key 原样写入；重复 key → 409；非法 key（含大写/空格，如 `Bad Key!`）→ 422；新文档默认归入「默认文档」。
- **两级权限可见范围**：
  - 构造角色仅授予 `doc.view` + `doc_groups=['用户文档']` → 列表只返回「使用说明」（用户文档分组），开发文档 → 404；无 `doc.edit` → 编辑 403；无 `doc.create` → 新建 403。
  - 普通成员（默认 `doc.view`、`doc_groups` 空）→ 看到全部 7 类内置文档；无 `doc.edit` → 编辑 403。
  - 管理员（`doc.view/edit/create/sync` 齐全）→ 可建/改/同步。

### 4.6 指标达成状态判定 (achievement)
- **用例**：`progress_tone` 在 ratio≥1→ahead、0.7≤ratio<1→near、<0.7→risk、rate≥1→done、缺失→none；`light_of` 缺目标→none。

**验证脚本通用写法要点**：
1. `POST /auth/login` 拿 `Set-Cookie`，解析 `access_token` 随后续请求带 Cookie（**线上代理改写 Authorization，Bearer 失效**）。
2. 针对新行为发真实请求，校验字段/结构，必要时建临时数据。
3. 用 `try/finally` 删除临时数据，确认生产无残留。
4. 前端校验：从入口 chunk 图解析懒加载块（如 `DashboardView-*.js`）再 fetch 校验字符串，只扫入口块会漏掉。

## 7. 回归要点与红线检查
- **每次发布必查**：
  1. 本地 pytest 全绿（当前 173）。
  2. 前端 build 通过。
  3. 执行对应 round 的 verify_live 脚本，临时数据已清理。
  4. 确认生产未注入本地业务数据（`start.sh` 无 `SEED_DEMO`）。
- **易回归点（历史踩坑）**：
  - Pydantic v2 `field_validator` 不校验「被省略且有默认值」的字段——强制必填须去掉默认值或用 `model_validator(mode="after")`。
  - 新增可保存阶段时，必须同步 `ALL_PROJECT_STAGE_VALUES` / 标签映射 / importer，避免漏改。
  - 漏斗/需求分析阶段口径改动需同步前端筛选标签。
