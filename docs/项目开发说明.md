# 车队经营看板 · 项目开发说明（迭代记忆）

> 用途：记录各轮迭代的决策、变更与经验，供团队与接手 Agent 快速回溯。　|　最后更新：2026-10-18（Round 36）

---

## 项目定位
面向合资物流公司的车队经营管理平台，整合**市场项目商机、经营指标、任务执行**于统一看板，支撑总部运营与分支人员安全协作。当前为单租户演进形态（多租户改造为后续方向）。

## 关键决策（ADR 式）
- **D1 可保存阶段 ≠ 漏斗阶段**：落库校验用 `ALL_PROJECT_STAGE_VALUES`（10/25/50/75/90/100/0），漏斗遍历 `MARKET_STAGES`（不含 0）。避免「保存流失被拒」类 bug。
- **D2 预估消化取整用 half-up**：`int(x+0.5)`，规避内置 `round` 的银行家舍入（2.5→2），符合业务直觉。
- **D3 字典只启停不删除**：已存在配置不丢，停用后枚举从关联下拉消失；删除路由整体移除。
- **D4 进展只追加**：项目/任务进展均为时间轴追加，编辑不直接改快照，保证审计连续。
- **D5 文档存库 + 源文件同步**：文档源在 `docs/`，发布复制到 `backend/bundled_docs/`，`POST /system/docs/sync` 写入库，实现「每次迭代自动更新」，且管理员可在界面「同步最新 / 编辑」。

## 经验沉淀
- 本项目是**原型驱动**产物：先跑通再补文档（`设计文档.md`/`skill文档.md` 均于 Round 36 补写）。
- 部署必须「build → cp dist→static → deploy」三步，漏拷贝会导致线上前端陈旧（Round 35 踩坑）。
- 线上验证须用 Cookie 鉴权（代理改写 Authorization）；验证脚本用临时数据并清理，遵守红线。
- 前端菜单是硬编码，新增页面要同时改 `router/index.ts` 与 `AppLayout.vue` 两处。
