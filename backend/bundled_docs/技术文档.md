## 1. 系统架构

```
┌─────────────────────────────┐         ┌──────────────────────────────────┐
│  前端 (Vue3 + TS + Vite)    │  HTTPS  │  后端 (FastAPI + SQLAlchemy 2.0)  │
│  frontend/dist → backend/   │ ──────▶ │  SQLite 单库 (沙箱托管)           │
│  static/（由部署挂载）       │ ◀────── │  Pydantic v2 校验                 │
└─────────────────────────────┘  Cookie │  RBAC + scope 数据隔离            │
                                        └──────────────────────────────────┘
```

- **前端**：Vue 3 `<script setup>` + TypeScript + Vue Router + Pinia；构建产物 `frontend/dist` 必须 `cp -R` 进 `backend/static/` 后随后端一起部署。
- **后端**：FastAPI，SQLite 单文件库；会话用 HttpOnly Cookie（`access_token`），**注意线上反代会改写 `Authorization` 头，API 鉴权走 Cookie 而非 Bearer**。
- **部署**：`workbuddy_sites_deploy`，`directory=backend/`，`startCmd=bash start.sh`（监听 `$PORT`、0.0.0.0，启动幂等 seed）。

## 4. 关键模块实现

### 4.1 市场项目漏斗 `services/funnel.py`
- `load_probs()`：`configured.get(stage, stage/100.0)`，库未配回落阶段百分比。
- 三漏斗：项目数 / 车头需求 / 挂车需求；`stages[]` 为**各阶段当前数量口径，不向上累计**。
- 加权预测 `forecast{tractor,trailer}` = Σ(需求 × prob)，`round` 取整。

### 4.2 车辆需求分析 `build_demand_analysis`
- 车头按 `(model, battery)` 组合聚合；挂车按 `model` 聚合。
- `digest`（预估消化数量）= Σ(该组合下各项目需求 × 项目阶段 prob)。
- **取整 `_round_half_up`**：`int(x + 0.5)`（half-up，规避内置 `round` 的银行家舍入 2.5→2；Round 35）。
- 阶段集合 `DEMAND_ANALYSIS_STAGES = MARKET_STAGES + [CHURN_STAGE]`，流失 `stage=0`、prob=0 **不进漏斗**。

### 4.3 指标达成状态 `services/achievement.py`
- `progress_tone(rate, time_progress)`：唯一口径
  - `done` rate≥1 ｜ `ahead` ratio=rate/时间进度 ≥1 ｜ `near` 0.7≤ratio<1 ｜ `risk` ratio<0.7 ｜ `none` 未录入。
- `light_of`：红黄绿灯 `green/amber/red/none`（缺目标/实际→none）。
- `time_progress_of(period)`：(年初至数据截至日天数+1)/全年天数。
- 加权达成率 = Σ(rate×weight)/Σweight；回款率并入主行（`family=collection`，默认目标 0.95）。

### 4.4 阶段落库校验 `api/v1/market.py`
- 统一白名单 `ALL_PROJECT_STAGE_VALUES = [10,25,50,75,90,100,0]`（constants.py，Round 34 新增）。
- `_apply_payload` 用其校验，放行 `0`（流失）；非法 stage → 422。
- `_STAGE_LABELS` / importer 同步纳入流失（编辑后 stageLabel 正确回填「流失」）。

### 4.5 数据字典启停 `api/v1/system.py`
- 移除 `delete_dict`；新增 `POST /system/dicts/{id}/status`（`DictStatusIn{status:active|disabled}`）。
- 前端按钮改为「停用/启用」+ 状态徽章；停用的枚举不再出现在关联下拉。
- seed 幂等 upsert：本地注入 `battery_capacity`(400度/423度/600度/352度)，不覆盖线上已配值。
- `doc_group` 字典（code=`doc_group`）预置三个枚举：**默认文档 / 用户文档 / 开发文档**，供文档中心分组下拉与角色可见范围选择。

### 4.6 权限与数据范围 `services/scope.py` + `constants.py`
- scope 四档作用于**任务 + 市场项目**；驾驶舱/指标全公司口径。
- 默认权限兜底 `DEFAULT_PERMS_FOR_ALL = [task.detail, market.detail, sys.config.view, download.view, doc.view]`。
- **文档中心两级权限（Round 37 新增）**，权限清单 `PERM_GROUPS` 新增 `doc` 分组：
  - `doc.view`（菜单）：能否进入文档中心。
  - `doc.edit`（按钮）：编辑文档（改标题/分组/内容），doc_key 不变。
  - `doc.create`（按钮）：新建文档。
  - `doc.sync`（按钮）：从 `bundled_docs/` 同步（管理员）。
- 第二级「分组可见范围」由 `Role.doc_groups`（JSON 数组）承载：**空数组 = 可查看全部分组**；非空则仅能看到列表中的分组。后端 `api/v1/doc.py` 用 `_allowed_groups` 过滤 list/get。前端菜单 `doc` 的 perm 改为 `doc.view`（原 `sys.config.view`）。
- **UI 位置（Round 37 微调）**：角色编辑弹窗的「权限配置」面板内，文档中心菜单（menu=`doc`）的「菜单权限 / 操作权限」勾选区下方，用 `<template v-if="g.menu==='doc'">` 紧跟渲染「文档分组可见范围」多选（来自 `doc_group` 字典，未勾选文档中心菜单时禁用）；该控件整体仍在权限配置板块内，而非独立置于面板之外。

### 4.7 文档中心（分组 + 两级权限）`api/v1/doc.py` + `models/doc.py` + `docs_meta.py`
- **存储**：`system_doc` 表（`doc_key` 唯一），新增 `doc_group` 字段（取值来自 `doc_group` 字典，默认「默认文档」）。
- **接口**：
  - `GET /system/docs`（列表）：需 `doc.view`，只返回当前角色 `doc_groups` 可见分组的文档，含渲染 `html`。
  - `GET /system/docs/{key}`：需 `doc.view`，分组不可见 → 404。
  - `PUT /system/docs/{key}`：需 `doc.edit`；可改 `title`/`fmt`/`group`/`content`，**doc_key 不变**；仅 `content` 变更时 `version+1`。
  - `POST /system/docs`：需 `doc.create`；`key` 省略时后端自动生成 `doc_<8位hex>`，校验 `^[a-z0-9_]{1,32}$`（非法 → 422）；重复 key → 409；每个文档必须有分组，缺省「默认文档」。
  - `POST /system/docs/sync`：需 `doc.sync`；从 `backend/bundled_docs/` 读源文件覆盖写入，并按 `docs_meta.DOC_GROUPS` 统一维护内置文档分组。
- **渲染**：`docs_meta.render_html`——`html` 格式原样返回（前端 iframe srcdoc），`markdown` 用 `markdown` 库转 HTML（`tables`/`fenced_code` 扩展）。
- **自动更新机制**：源文件在 `docs/`，发布时复制到 `backend/bundled_docs/`，调 `sync` 写入库；seed 也会在行缺失时从 bundle 载入初始内容。前端「文档中心」从库读取渲染。
- **内置文档与分组映射**（`docs_meta.DOC_GROUPS`）：`usage`→用户文档，其余（prd/tech/test/visual/skill/devnotes）→开发文档。设计文档已合并入技术文档，不再单独存在。

## 9. 设计原则与信息架构（合并自设计文档 v1.0）

### 9.1 设计原则
- **原型驱动 > 文档驱动**：先让系统跑起来，再补设计说明（本档即迭代产物）。
- **简洁透亮**：表格去竖线、仅保留行分割线；卡片化信息块；状态用色彩而非长篇文字。
- **决策可追溯**：关键取舍（如「可保存阶段」与「漏斗阶段」分离）在代码注释与项目记忆中留痕。
- **权限即界面**：菜单/按钮按 RBAC 显隐，用户只见其权限内的功能，无越权入口。

### 9.2 信息架构
```
经营驾驶舱（dashboard.view）
  ├─ 分析总结卡
  ├─ 市场项目概览（三漏斗：项目数 / 车头 / 挂车 + 加权销量预测）
  ├─ 车头需求漏斗
  ├─ 车辆需求分析（车头×电池容量 / 挂车×车型，双表）
  └─ 转化概率配置弹窗（dashboard.config）
核心指标 · 年度目标（metric.view）
  ├─ 公司整体目标（表）
  ├─ 指标监控（卡片）
  └─ 项目公司指标（表）
项目管理（market.view）     任务管理（task.view）
系统配置（sys.config.view）
  ├─ 数据字典      ├─ 账号管理      ├─ 下载中心
文档中心（doc.view，Round 37 重构为独立菜单）
  └─ 按分组归类：用户文档（使用说明）/ 开发文档（PRD/技术/测试/视觉交互/Skill/项目开发说明）
```

### 9.3 导航与权限模型
- 左侧菜单为**硬编码数组**（`AppLayout.vue` 的 `ALL_MENUS`），与路由 `meta.perm` 双声明、保持一致。
- 菜单可见性 = `auth.hasPerm(perm)`；文档中心菜单 perm 现为 `doc.view`（Round 37 由 `sys.config.view` 调整而来）。
- 数据范围（scope）仅作用于**任务**与**项目管理（商机）**；驾驶舱与指标全公司口径。
- **文档中心两级权限**：① 菜单级 `doc.view` 决定是否进得去；② 分组级 `Role.doc_groups` 决定能看哪些分组的文档（空=全部）。

## 12. 异常处理与文案
- 登录失败统一「账号或密码错误」，不泄露账号是否存在；停用账号返回 403。
- 表单校验错误就近提示（如电池容量必选字典项、阶段非法拦截、文档 key 非法 422）。
- 危险操作（删除项目公司、停用账号）走二次确认弹窗并展示影响预检。
