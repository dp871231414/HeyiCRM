# 车队经营看板 · 产品需求文档（PRD）

> 版本：v1.1（汇总至 Round 37 功能）　|　最后更新：2026-10-19　|　适用系统：和毅车队经营看板（heyi-fleet-dashboard）

---

## 1. 产品概述

### 1.1 背景与目标
面向合资物流公司的车队经营管理平台，将分散在表格/邮件中的**市场项目商机、经营指标、任务执行**整合为统一看板，支撑总部运营与分支人员在同一套数据上协作。核心目标：

- 让经营管理者一眼看清「市场项目进展 → 车头/挂车需求 → 年度指标达成」的全链路。
- 让一线人员按各自数据范围（scope）维护商机与任务，不越权、不互扰。
- 通过按钮级 RBAC + 数据范围，实现「总部管控 + 分支自治」的安全协作。

### 1.2 目标用户与角色
| 角色 | 默认 scope | 说明 |
|---|---|---|
| 系统管理员 `admin` | all（全公司） | 内置，不可删；拥有全部权限 |
| 部门负责人 `dept_head` | dept_sub（本部门及下属） | 管理本部门商机与任务 |
| 普通成员 `member` | self（本人） | 仅维护本人名下任务/可见范围 |

> scope 四档：`self` 本人 / `dept` 本部门 / `dept_sub` 本部门及下属 / `all` 全公司。**scope 仅作用于「任务模块」与「市场项目（商机）模块」**；经营驾驶舱与核心指标按角色权限开放、全公司口径返回。

### 1.3 术语表
- **市场项目（商机）**：销售侧商机，前缀 `MP`。含阶段、车头/挂车需求明细。
- **项目公司**：独立核算组织，前缀 `PC`，挂在全公司 `CO` 下，维护其年度指标。
- **核心指标**：年度目标 / 监控指标 / 项目公司指标三类（`annual` / `monitor` / `project`）。
- **达成率 / 进度状态**：`rate` 实际÷目标；`tone` 进度状态（达成率 vs 时间进度）。
- **转化概率（prob）**：各市场阶段的成交概率，全系统共用一份 `funnel_config`。
- **流失**：阶段 `stage=0`、转化率 `0%`，仅用于标记已流失项目，不进销售漏斗。

## 3. 各模块需求详述

### 3.1 经营驾驶舱
**输入**：统计周期 `period`、组织视角 `org_id`（默认 `CO`）、二级部门 `dept`（市场部子公司筛选，可选）。
**输出区块**：
1. **分析总结卡**：headline / 总体 verdict（good/warn/bad/none）/ wins / points / risks。
2. **市场项目概览（三漏斗）**：项目数漏斗、车头需求漏斗、挂车需求漏斗，每个阶段 `{stage,label,prob,count,tractor,trailer}`，各阶段为**当前数量口径不向上累计**；并给出加权销量预测 `forecast{tractor,trailer}`（取整）。
3. **车辆需求分析**（详见 3.1.4）。
4. **项目公司经营对比表、指标监控卡、部门任务完成度、风险与异常**。
5. **转化概率配置弹窗**（需 `dashboard.config`）：整份保存 6 阶段转化概率，立即影响销量预测。

**3.1.1 市场项目概览（漏斗）规则**
- 阶段 `MARKET_STAGES`：10 项目导入 / 25 市场尽调 / 50 初审通过 / 75 联合评审通过 / 90 签约落地 / 100 交车投运。
- 转化概率默认 = 阶段值/100；库已配则用配置值。预测 = Σ(各项目需求数 × 该阶段转化概率)。
- 部门筛选只统计该二级部门负责人名下项目。

**3.1.2 车头需求漏斗（原名「车辆需求漏斗」，Round 31 改名）**
- 以车头需求维度绘制漏斗，阶段口径同 3.1.1。

**3.1.3 阶段筛选标签（含转化率后缀）**
- 阶段标签带转化率百分比后缀，默认「全部」；点击仅显示该阶段数据。

**3.1.4 车辆需求分析（Round 32/33 新增）**
- 左右等宽双表：
  - **车头需求**：按（车辆型号 × 电池容量）组合汇总，列：车辆型号 / 电池容量 / **总需求数(辆)** / **预估消化数量(辆)**。
  - **挂车需求**：按车型汇总，列：挂车型号 / 总需求数(辆) / 预估消化数量(辆)。
- **预估消化数量** = Σ(该组合下各项目需求数 × 项目所在阶段转化概率)，**四舍五入取整**（Round 35）。
- 阶段筛选标签含「流失」(`stage=0`, prob=0%)，置于交车/投运之后；流失阶段计入总需求但预估消化为 0。
- 表格简洁透亮，仅行分割线无竖线，各自独立滚动。

### 3.2 项目管理（商机）
**输入**：列表筛选 `keyword`/`stage`/`page`/`size`；新建/编辑含 `name,description,progress(必填),tractorRequirements[]{model,battery,qty}, trailerRequirements[]{model,qty}, stage, owner, owner_dept_id, owner_dept_name`。
**输出**：列表项含 `tractorDemand/trailerDemand`（=明细 qty 汇总）、`stageLabel`、最新进展 `latestProgress`、创建人/部门等；详情含进展时间轴。
**规则**：
- 阶段落库允许值 `ALL_PROJECT_STAGE_VALUES = [10,25,50,75,90,100,0]`（含流失）；非法 stage → 422「项目阶段不合法」（Round 34 修复）。
- 车头电池容量下拉取自数据字典 `battery_capacity`（400度/423度/600度/352度，Round 31 联动）。
- 进展记录**只能追加**，编辑不直接改进展快照。
- 需求明细整份替换（先删后插）；删除级联清除进展与需求。
- 导出落「下载中心」。

### 3.3 核心指标·年度目标
**输入**：统计周期 `period`（默认当月，年度目标按年存）、组织视角 `org_id`（默认 `CO`）、目标值/累计完成值/回款金额。
**输出（三大块，权限互相独立）**：
1. **公司整体目标**：表 `annual[]`，列：指标/年度目标/累计完成值/完成率/回款/回款率/状态/操作。状态用 `tone` 徽章（已达成/领先/偏慢/滞后/未录入），完成率 vs 时间进度显示 `vsTime` 差值。
2. **指标监控**：卡 `monitor[]`，无目标值、不判灯，仅录入当期快照，显示上期值。
3. **项目公司指标**：表 `project{companies[],metrics[]}`，按指标列目标/累计完成/达成/回款率，并显示公司完成率（各指标达成率均值）。
**业务规则**：
- 达成状态唯一口径 `progress_tone(rate, time_progress)`：`done`(rate≥1) / `ahead`(ratio≥1) / `near`(0.7≤ratio<1) / `risk`(ratio<0.7) / `none`(未录入)。
- 时间进度 = (年初至数据截至日天数+1)/全年天数。
- 加权达成率 = Σ(达成率×weight)/Σweight。
- 回款率 = 累计回款/累计销售收入（并入主行展示）。
- 编辑权限按块独立：公司整体目标→`metric.edit_company`（且须公司视角）；监控→`metric.edit`；项目公司→`metric.edit_project`。仅看权限不看 scope。

### 3.4 任务管理
**输入**：筛选 `keyword/dept_id/status(done/overdue/due_soon/normal/risk)`；表单含任务组（下拉搜索+分页+内联增改删）、责任人、是否异常、目标/已完成/单位/进度、计划起止、描述、进展。
**输出**：`TaskItem` 含完成进度、状态等级、剩余天数；部门完成度 `dept-stats`；导出落下载中心。
**规则**：
- 状态判定下推 SQL：`done`(done≥target) / `overdue`(未完且 end<今天) / `due_soon`(未完且 end==今天且非异常) / `normal` / `risk`(abnormal 且未完且 end≥今天)。
- 进展只能追加；任务组唯一=名称+责任人，系统默认 `TG_NONE` 不可删。
- 默认分页 200，上限 2000（分组视图需全量）。

### 3.5 数据字典
**输入**：`GET /system/dicts?code=`；新增/编辑 `SysDictCreate{name,code,items[]{value,sort}}`；启用/停用 `POST /system/dicts/{id}/status{status:active|disabled}`。
**输出**：`SysDictOut{id,code,name,status,items[]}`。
**规则**：
- **已存在配置不允许删除，只能启用/停用**（Round 31）。停用的字典其枚举值不再出现在关联下拉。
- 字典编码固定消费：`vehicle_model`、`trailer_model`、`battery_capacity`。

### 3.6 系统管理（账号/组织/角色）
- **账号**：列表 `keyword/dept_id/status`；新增/编辑含 `scope(必填)`；启用/停用（不可停用当前登录账号）；删除预检（被引用则阻断）；导入。
- **组织**：树形；`D01` 市场部锁定不可删，`CO` 根不可删；删除前若有下级/账号则阻断，任务上移上级。
- **角色权限**：`GET /permissions` 拉取权限树；内置角色不可删；默认权限兜底 `DEFAULT_PERMS_FOR_ALL`。

### 3.7 下载中心
- 列表/任务/市场项目「导出」按钮不直接下载，而是落盘生成 `DownloadRecord`，仅本人可见/下载/删除。

### 3.8 登录与鉴权
- 账号密码登录，下发 HttpOnly Cookie（`access_token`）；登录失败统一文案不泄露账号存在性；停用账号 403。
- 偏好键白名单：`rowHeight` ∈ `default/high/ultra`。

### 3.9 文档中心（Round 37 重构：分组 + 两级权限）
- **入口**：左侧独立菜单「文档中心」（菜单 perm `doc.view`，默认全员可看；原「系统配置 → 使用说明」已升级拆分）。
- **分组（每个文档必须有分组）**：文档按分组归类，分组来自数据字典 `doc_group`，初始枚举为 **默认文档 / 用户文档 / 开发文档**；新文档默认归入「默认文档」。内置文档分组：`usage`（使用说明）→ 用户文档，其余（PRD/技术/测试/视觉交互/Skill/项目开发说明）→ 开发文档。
- **两级权限模型**：
  1. **菜单级 `doc.view`**：决定能否进入文档中心；
  2. **分组级 `Role.doc_groups`**：决定能看哪些分组的文档（空数组 = 可看全部分组）。
  - 例：某角色授予 `doc.view` 且 `doc_groups=['用户文档']`，则其只能进入文档中心看「使用说明」，看不到开发文档分组下的内容。
- **输出方式**：左侧文档列表按分组分块（当前账号可见分组才显示）；管理员可「同步最新」（从源码刷新）、「编辑」（内容区上方提供分组下拉与命名输入，改命名不改变后台文档 key）、「新建文档」（`doc.create`）。
- **输出结果**：右侧渲染所选文档内容——HTML 类以富文本呈现（iframe srcdoc），Markdown 类转排版网页（`.doc-prose`）；每篇显示版本、更新时间、所属分组。
- **存储与自动更新**：文档内容存 `system_doc` 表（含 `doc_group` 列）；每次迭代将 `docs/` 复制到 `backend/bundled_docs/` 后调 `POST /system/docs/sync` 写入数据库，实现「每次迭代自动更新」（Round 36 引入，Round 37 扩展分组与权限）。

## 4. 非功能需求
- **性能**：列表默认分页，分组视图需全量取数；趋势数据并发优化为批量一次请求（见技术文档）。
- **安全**：按钮级 RBAC + 数据范围隔离；登录 IP 日志用于防劫持与外部探测；登录失败不泄露账号存在性。
- **数据一致**：进展只追加、明细整份替换、字典不删只停用。
- **可审计**：关键写操作记录审计日志（指标/项目/任务变更）。
